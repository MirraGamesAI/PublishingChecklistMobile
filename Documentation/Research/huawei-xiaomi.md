## Build facts

### Huawei AppGallery (outside mainland China)

- Package format: APK or AAB. AppGallery Connect also accepts RPK, APP (HarmonyOS) and EXE; not relevant for Unity Android builds.
- Size limits: APK at most 4 GB; AAB upload at most 1024 MB, and the APKS generated from it at most 150 MB download size. For a Unity game above 150 MB, ship an APK (Play Asset Delivery is not supported). No OBB rule was found.
- AAB specifics: App Signing must be enabled before the first AAB upload (Huawei-generated key recommended, or upload your own key with pepk.jar); AppGallery re-signs and verifies in 2-5 minutes; Play Asset Delivery must be off; dynamic feature modules need fusing true or the Dynamic Ability SDK.
- Minimum and target API: no current official rule found. The manifest must declare both fields (error codes 1003, 1004). A third-party report (HuaweiCentral, 2023, page blocked by a bot check, seen only as a search result) says target API 30 became mandatory for new apps from 2023-10-31. Google Play's current target is far higher, so a shared codebase already exceeds it.
- 64-bit: a 64-bit package is required for new apps and updates since 2022-02-01 (third-party copy of the Huawei notice; the official notice page now returns 404).
- 16 KB page size: not mentioned in any Huawei source found.
- Signing: updates must keep the signing key of the released version. Changing it stops existing users from updating directly.
- Package name: must match the AppGallery Connect app and cannot be changed. If the same package exists on Google Play under the same owner, Huawei may require an ownership declaration email (release FAQ).
- Device fact: Huawei phones from the Mate 30 onward are HMS-only (no GMS); older models have GMS or GMS plus HMS. AppGallery can serve different APKs to GMS and HMS devices.
- Required SDKs: none is mandatory for Android games outside the Chinese mainland in the current Review Guidelines. Billing: HUAWEI IAP is recommended (guideline 6.4). Login: HUAWEI ID or Game Service sign-in is not required by the guidelines; the game "Making Preparations" page requires Huawei game sign-in only for HarmonyOS games. Ads: Petal Ads (Ads Kit) is optional, and no rule forbids third-party ad networks. Saves: no Huawei cloud save requirement. Review prompt: AppGallery in-app comments API (outside mainland only).
- Forbidden or non-working SDKs: anything that needs Google Play services on HMS-only devices (Play Billing, Play Games Services, Google Sign-In, FCM, Play In-App Review, Play Integrity, GAID). Self-update or hot-code SDKs are forbidden by guideline 3.9.
- Permissions and APIs: request permissions at the moment of use with a stated purpose; no location for ads; use OAID (not IMEI or MAC) for ad identification and honor "Disable personalized ads".
- Privacy: an in-game privacy policy link that matches the AppGallery Connect one; consent before any SDK collects data; an independent personalized-ads switch; account deletion within 15 working days. AppGallery Connect can host a privacy statement if the studio has none. Privacy FAQ I also contains mainland-China-only items (a Simplified Chinese policy, the National SDK Management Service Platform), which were skipped.
- Content rating: Huawei's own questionnaire produces a suggested rating that the developer confirms. Outside mainland China: 3+, 7+, 12+, 16+, 18+. Brazil: AL, A6, A10, A12, A14, A16, A18.
- Review process: review usually takes 3-5 working days, and rejections arrive by email. AppGallery Connect runs an automatic validity check on upload (Passed, To Be Optimized or Failed). Huawei suggests asking its technical support to pre-check game packages. Reviewers need a test account for login-gated features. Games need copyright qualification files, and Vietnam requires a game license.

### Xiaomi GetApps (global)

- Package format: APK or APKS (bundletool build-apks with --ks signing); AAB is not accepted. An optional APK expansion package can be uploaded alongside the main APK.
- Size limits: not published in the docs found (open question).
- Minimum and target API: no store rule found. The compatibility requirement covers Android 10-14 and all global Xiaomi and Redmi models released in the past two years. IAP-SDK 1.1.8 adds support for targetSdkVersion 35.
- 64-bit: no explicit rule found.
- Signing: the APK must be signed; updates must use the same key as the live version and a higher versionCode. PSV is recommended: same package name and signature as Google Play (the Play app-signing key, obtained by downloading the "Signed universal APK" from a saved Play internal-testing draft) and a versionCode above Google Play's.
- Ownership: no verification is needed if the Xiaomi account email equals the Google Play developer email. Otherwise an email code is sent to the Google Play contact email. If the app is not on Google Play, the console requires empty APK signature authentication (com.xiaomi.getapps.signature.verification.apk, at most 4 MB, signed with apksigner, v2 or v3) and the Application Copyright Commitment.
- Required SDKs: billing must use the Xiaomi GetApps IAP-SDK (com.xiaomi.billingclient:billing, latest 1.1.9, from Maven Central) when the game sells paid items. GetApps IAP supports one-time products and subscriptions in the listed countries, including Russia and Uzbekistan, and requires an enterprise developer account. No Xiaomi login, ads, cloud save or review-prompt SDK was found to be required. Ads: AdMob is supported when the AdMob app is registered with the store "Xiaomi GetApps".
- Forbidden: third-party payment channels without Xiaomi's consent (Distribution Service Agreement), notification-bar, floating and offerwall ads, BIND_ACCESSIBILITY_SERVICE and BIND_DEVICE_ADMIN abuse, keep-alive and forced-startup permissions, runtime download of executable code, app-market features.
- Distribution: GetApps covers 110 countries and regions; the Distribution Service Agreement territory excludes the Chinese mainland. The contracting entity is Xiaomi Technology Netherlands B.V. for the EU, Zhigu Corporation Limited for Russia and Pinecone HK Limited for other regions. The revenue share is 70/30 (80/20 for subscriptions).
- Content rating: Xiaomi's own table (3+, 7+, 12+, 16+, 18+), selected in the console.
- Review process: a machine test (Monkey and traversal, security scan by five vendors, static permission detection) followed by manual review, usually within 3 working days (the APKS guide says 1-3 business days). A cloud test platform gives a preliminary report.
- Developer verification: GetApps is one of Google's Android developer verification partner stores.

## Conflicts and open questions

1. Huawei guideline 5.4(3) forbids showing the close button "only after a delay or when a countdown ends". This conflicts with the standard rewarded-video flow (close appears after the video ends) and with non-skippable interstitial timers used by AdMob, AppLovin and others. It is unclear whether reviewers apply it to opt-in rewarded ads. Verify with Huawei before release, or configure the Huawei build's ad units to be closable immediately.
2. Xiaomi Policy 3.3.5 forbids any in-game update prompt. Huawei allows optional prompts, and Google Play offers the In-App Updates API. A forced or optional "new version available" dialog must be disabled in the Xiaomi build.
3. Xiaomi PSV (same package name and signing key as Google Play, higher versionCode) conflicts with the studio's one-build-per-store setup. The Xiaomi build (GetApps IAP) and the Google Play build (Play Billing) would share a package name and key. Once Google Play has a higher versionCode, Play's auto-update can replace the Xiaomi build on the device, and purchases made with GetApps IAP would then not be visible to Play Billing. Xiaomi's "Get the app signed by Google Play" flow also asks developers to upload the Xiaomi-IAP build to a Play internal-testing draft, which may conflict with Google Play's Payments policy and with the HMS-free rule for Play builds. Decide a versionCode scheme, and confirm whether a separate package name is acceptable to Xiaomi (PSV is only "recommended").
4. The Xiaomi Developer Agreement 2.2 says using GetApps Payments is optional ("may choose"). Review Policy 7.1 and the Distribution Service Agreement require the Xiaomi SDK and treat third-party payment without consent as a material breach. Treat GetApps IAP as mandatory for paid items.
5. Xiaomi Policy 6.4.4 ("must not collect data on minors") and 6.4.3 ("must not require users to share ... birthdays") conflict with 13+ games that have players aged 13-17 and with neutral age gates used for COPPA or GDPR consent. Clarify with Xiaomi whether an optional age gate is acceptable and whether ad and analytics SDKs must run in a reduced-data mode for players under 18.
6. Huawei target API: no official current requirement was found. The only figure (API 30 for new apps from 2023-10-31) comes from a third-party news report seen only as a search result, so treat it as unverified. Huawei and Xiaomi publish no 16 KB page-size rule; Google Play's 16 KB requirement is covered by the Google Play research.
7. Huawei 64-bit: the official notice URL is dead (404). The rule rests on a third-party copy. Xiaomi publishes no 64-bit rule; shipping arm64-v8a is assumed for Xiaomi but not verified.
8. HUAWEI ID and Game Service sign-in: the current Review Guidelines do not require them for Android games outside the Chinese mainland. Older (2021) joint-operations rules required sign-in calls only for mainland China, which is out of scope. Huawei's current game "Making Preparations" page requires Huawei game sign-in for HarmonyOS games, and links an Android game to its HarmonyOS version on HarmonyOS 5.0 and later. If the studio ever ships a HarmonyOS-native version, sign-in becomes required. Confirm the Android rule with Huawei technical support (Huawei recommends a pre-review package check for games).
9. The Xiaomi rejection reason "failure to synchronize game data" was not found in any global GetApps document. It appears to belong to Xiaomi's mainland-China joint-operations rules (data interoperability between channels), which are excluded. If a global review email cites it, record the exact wording.
10. Xiaomi package size limit and target API rule are not published. The Machine Testing Guidelines page is outdated (it still lists Android 5-9), while the Policy requires Android 10-14.
11. Petal Ads: no official country list was found. Huawei Ads does not allow individual accounts. The Russia FAQ shows Petal Ads operates in Russia. On HMS-only Huawei devices the Google advertising ID is unavailable, so ad mediation fill (AdMob and others) on those devices must be tested; networks that support OAID may perform better. No Huawei rule restricts third-party ad networks.
12. Google's Android developer verification applies to certified Android devices. HMS-only Huawei phones are not Google-certified, and AppGallery is not in the partner list, while GetApps is. Older GMS Huawei phones are certified, so registering the Huawei build's package name and key is advisable once verification goes global in 2027.
13. Russia and GDPR: neither store adds Russia-specific data rules beyond "comply with applicable laws" (Huawei 7.4, Xiaomi 6.1.1). Russia-specific obligations found were Huawei's Petal Ads ERIR registration for Russia and Xiaomi's Russian contracting entity (Zhigu Corporation Limited). Data localization under Russian law is not mentioned by either store.
14. Huawei guideline 1.16 and Xiaomi Policy 4.8.3 forbid showing other platforms and app stores. Shared UI that shows Google Play Games achievement buttons, "Rate on Google Play" text or Play badges must be replaced per store build.
