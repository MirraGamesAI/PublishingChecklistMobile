| 1 | RuStore | A | The game launches and runs without crashes, freezes, force closes or layout errors, all declared features work, and it is tested on current Android versions; RuStore names Android 8.0 as the minimum supported version. | must | https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps |
| 2 | RuStore | N | The RuStore build contains no protection or licensing mechanism that blocks install, launch or use when the app comes from RuStore (RuStore names Google Play Integrity as an example); such apps are removed from publication. | must | https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps |
| 3 | RuStore | N | The release build has android:debuggable="false", is not signed with a debug certificate, uses no malware-style code packers, sets no inflated priority on intent filters for system intents, and has no abnormal number of trackers or ad modules without user disclosure; each of these is a rejection signal in the automated scan. | must | https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps |
| 4 | RuStore | N | Each APK or AAB file is at most 5 GB, and every APK that RuStore generates from an AAB is also at most 5 GB (check with bundletool build-apks --mode=universal). | must | https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/new-version-app/upload-aab |

| 15 | RuStore | M | The game contains no new (non-classic) depictions of alcohol, tobacco or nicotine use and no gamification of their consumption, in any age category. | must | https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps |

## Build facts

### RuStore

- Package format: APK or AAB. One version can hold several files: main file, a Huawei/Honor file with HMS, a TV file, and files with different signatures (for example a Google Play-signed copy); the main file must be the one with the non-Google signature. Processed uploads are kept 14 days. Sources: https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication
- Size limits: APK or AAB at most 5 GB; every APK generated from an AAB at most 5 GB.
- Minimum and target API: moderation tests on current Android with Android 8.0 (API 26) as the minimum supported version; the console reads minSdkVersion from the manifest. No targetSdkVersion minimum is published (not found). The Pay SDK 11.2.0 Unity guide sets Minimum API 24 and Target API 34; Yandex Mobile Ads Unity 8.6.0 needs target API 31 or higher.
- Signing: every APK signed; updates must match the previous signature. AAB: upload the app signing key via PEPK (RSA 2048 bit or more, Java 11 or later) plus the upload certificate in PEM, then sign the AAB with the upload key. Key replacement goes through support@rustore.ru and archives all versions, which must then be re-uploaded with the new key. RuStore recommends one locally stored key for all stores.
- Countries: availability is set per country in the console (Russia and other countries).
- Required SDKs: none is mandatory.
  - Billing: RuStore Pay SDK (Unity 11.2.0, packages ru.rustore.pay and ru.rustore.core from the RuStore Nexus npm registry, .tgz or .unitypackage; EDM4U; Custom Main Manifest, Main Gradle and Gradle Properties templates; Activity = UnityPlayerActivity). billingClient SDK is deprecated. Any other payment solution is allowed if declared. Commission 15% (resident agreement); non-residents 15% plus Russian taxes withheld where RuStore is tax agent. Pay SDK works in other stores too and accepts payment without RuStore installed (card, SBP, SberPay); subscriptions need VK ID.
  - Ads: no RuStore ad SDK requirement. Yandex Mobile Ads (Unity plugin 8.6.0) and VK Ads serve Russia; AdMob campaigns and AdMob Network do not serve users in Russia, and Russia-based AdMob accounts were paused in 2024-08.
  - Login: optional VK ID SDK; login must not depend only on third-party messengers.
  - Saves and game services: no RuStore cloud save; GameCenter SDK is beta (Kotlin and Unity docs). Personal data of Russian users must be stored in Russia (152-FZ art. 18 part 5).
  - Review prompt: RuStore In-app Review SDK, at most one launch per day.
  - Other optional SDKs: In-app Updates (needs current RuStore, signed-in user), Push, universal push, Remote Config, Install Referrer, Deeplinks. Since 6.0.0 all RuStore SDKs share one version number; use the BOM to keep them compatible.
- Forbidden in the build: Google Play Integrity or other checks that block RuStore installs; prohibited-level permissions; APK download or install of other apps; links to other app stores (so Google Play In-App Review or Play Store links must not ship in the RuStore build, by the links rule).
- Permissions: prohibited level = auto-reject; Dangerous, Special and Signature = sensitive, justified in the console (POST_NOTIFICATIONS is sensitive); REQUEST_INSTALL_PACKAGES is high-risk. RuStore states its permission rules are not stricter than Google Play's.
- Review process: automated scan (Kaspersky antivirus, MobSF vulnerabilities), manual moderation, optional security and legal review; decision within 72 hours; individuals may submit up to 10 apps per day; one appeal per decision to support@rustore.ru, answered within 30 calendar days. Sanctions: warning, version rejection, app block, account block.
- Non-residents: foreign companies register with constitutive documents, signatory proof and IP-rights documents in English or Russian (notarized translations), plus a mandatory link to the app in another store or the official site; non-resident individuals can pick their country. Monetization needs an additional agreement; payouts in RUB, CNY, KZT or USD, no transfers to US banks, minimum payout 100,000 RUB, paid within 30 days after signed acts; an annual tax residency certificate avoids a possible extra 20% withholding; chargeback evidence is due within 2 business days. Sources: https://www.rustore.ru/help/developers/monetization/monetization-foreign-company and https://www.rustore.ru/help/developers/faq/monetize/non-residents

### ONE Store

- Structure: one product in ONEconsole serves Korea and other countries; ONEconsole repackages the app for outside Korea. Korea and global ONE store are separate store apps (Korea installers com.skt.skaf.A000Z00040, com.kt.olleh.storefront, com.lguplus.appstore, market code MKT_ONE; global installers com.onestorecorp.gaa.storeapp, com.dti.folderlauncher, market code MKT_GLB). A Korea release is not required for global release. Distribution expanded to more than 123 countries and regions on 2026-08-24; the price table lists 124 countries including South Korea; a local price per country is required before review. Displayed ratings: GRAC (Korea), ESRB (Americas), DGSC (Taiwan), IARC Generic (others).
- Package format: APK or AAB (AAB is irreversible). Multi-binary (different APKs per device) only with APK and disabled app signing, and never for global distribution.
- Size limits: 2 GB per binary.
- Minimum and target API: AAB needs minSdkVersion 21 or higher; IAP SDK recommended environment is Android 6.0 (API 23) or higher and Java 11. No targetSdkVersion minimum is published (not found). targetSdk 30+: queries tag required for the IAP SDK; targetSdk 31+: explicit android:exported.
- Signing: options are ONE store-generated key (new apps only), same key as another app in the account, upload own key via PEPK, or disabled app signing (signed APK only). Updates must use the same upload key; a lost upload key is reset via Contact Us. App signing is required for global products with IAP or ALC. Since 2026-10-22 each binary shows a Google Android developer verification status (informational, does not block registration).
- Required SDKs:
  - Billing: ONE store IAP SDK V21 (21.04.00) or the third-party payment server API; Unity plugin built for Unity 2022.3.62f3 with Purchase v21.04.00 and App License Checker v2.2.1, imported as .unitypackage with EDM4U and a Custom Main Manifest. Testing with ONE Billing Lab and registered test IDs. Fees: Korea 20% (50% on amounts discounted by ONE store coupons or points), subscriptions 10%, ONEshop 8%, third-party payment 5%; outside Korea 20% (15% for Razer Gold and listed Taiwan methods), ONEshop 5% plus PG fees, third-party payment 5%; 50% fee reduction for developers at or below USD 5,000 per month.
  - Ads: ONE store in-app ads (IAA) exist only for web products; native games use third-party ad SDKs, which ONE store allows without constraints. The console Ad SDK Integration field should match the build.
  - Login: ONE store login (GaaSignInClient) is part of the IAP flow; other login SDKs are allowed.
  - Saves and game services: no ONE store cloud save or leaderboard service found; Google Play Games Services achievements and leaderboards can be linked by adding an OAuth credential for the ONE store build signing certificate.
  - Review prompt: no ONE store in-app review SDK found.
  - Optional: ALC (license check that only ONE store installs pass), StoreEnvironment.getStoreType() to detect the installing store.
- Forbidden in the build: links to other app markets, hybrid ONE store IAP plus third-party payment, onestore:dev_option and debug logging in release, debug signing.
- Permissions: no ONE store permission blacklist; permissions that infringe privacy can cause rejection; Korea requires the essential/optional notice before consent.
- Review process: mandatory for new apps and for binary, in-app, signing key, country, rating and privacy changes; automated virus and security scan (threats cause automatic rejection), device operation check, result by email; post-launch monitoring can return Approved (recommendation), Approved (warning) or Rejected (sale prohibited). AAB processing can take up to 30 minutes after approval.
- Korea-only obligations for the game: probability disclosure (types and odds), no result-based prizes, permission notice, chat caution notices, withdrawal-restriction marking for items, KRW prices; youth-restricted (19+) games must show GRAC age and content icons on the initial screen for at least 3 seconds (not relevant for 13+ games).

## Conflicts and open questions

1. Billing differs per store. Google Play requires Google Play Billing for digital goods; RuStore allows any payment solution if declared (RuStore Pay SDK optional); ONE Store requires ONE store IAP or its third-party payment API and forbids mixing the two. Each store build must ship only its own billing SDK.
2. RuStore removes apps whose protection blocks RuStore installs (Play Integrity named). Any Play Integrity, Play licensing or Play-only install checks in the Google Play build must be stripped from the RuStore build.
3. Signing keys conflict across stores. Google Play App Signing keys are Google-managed; RuStore and ONE Store both recommend one shared key so users can update across stores, and ONE Store's own generated key breaks cross-market updates and Google service fingerprints. Decide one locally held app signing key per package and upload it to RuStore and ONE Store (and Google Play via key upload) or use separate package names.
4. RuStore's language rule (section 6.2) still accepts English-only UI with a Russian description, while RuStore's own law summary says 168-FZ (in force 2026-03-01) requires Russian in app interfaces. Whether 168-FZ applies to non-resident developers is not stated; treat full Russian localization as required for the RuStore build.
5. 152-FZ art. 18 part 5 forbids foreign databases for primary storage of Russian citizens' personal data. Typical Unity cloud saves, Firebase, Google Play Games saved games and many analytics backends store data outside Russia. Open question for legal review: whether pseudonymous save data without account identifiers counts as personal data; if accounts or email exist, use a Russia-hosted backend for the RuStore build.
6. AdMob does not serve users in Russia (Google demand and bidding paused), so the Google Play ad stack does not monetize the RuStore audience; the RuStore build needs Yandex Mobile Ads or VK Ads (both must be declared in the RuStore console).
7. ONE Store supports only install-time asset packs in AAB; a Google Play build using fast-follow or on-demand Play Asset Delivery needs a different packaging for ONE Store.
8. Google Play In-App Review and Play Store links cannot ship in RuStore or ONE Store builds (both forbid links to other markets). RuStore has its own Review SDK; ONE Store has no in-app review SDK, so the rating prompt must link to the ONE store product page.
9. ONE Store Global does not distribute subscriptions (Korea only); a game that sells subscriptions on Google Play needs a non-subscription alternative in the ONE Store global build.
10. Neither RuStore nor ONE Store publishes a minimum targetSdkVersion (not found). The build will follow Google Play's target API anyway; check ONE Store's notes on queries (target 30+) and exported (target 31+).
11. Not found: any RuStore or Russian rule on loot box odds disclosure beyond the gambling ban; any ONE Store or Korean requirement for Korean-language game UI; an official ONE Store list of ONEshop payment countries (only press says 7).
12. The full MCST probability guide (PDF attachment) was not readable; display details in rule 62 come from a press summary and should be checked against the guide on the GRAC page before release in Korea.
13. The English RuStore guidelines page is an older version than the Russian moderation rules; where they differ, the Russian page is current (the non-resident agreement also says the Russian text prevails).
14. Not checked: Korea's domestic agent obligation for foreign game companies under the Game Industry Promotion Act; it does not change the build but may block publication for large publishers.
