## Conflicts and open questions

1. Signing across stores (recommendation). Store guidance conflicts: RuStore recommends and Aptoide requires the same signature as the Google Play version, while Samsung recommends a Galaxy-specific package name (Case 1) and notes that different keys only turn cross-store updates into an install error. Amazon always re-signs with its own key, and Huawei, ONE Store and Samsung (AAB) can re-sign with a store-managed key. Recommendation: use one studio-held signing key for every non-Play store that lets the studio supply the key (RuStore, Aptoide, Xiaomi, Huawei and Samsung by uploading that key to their signing service, ONE Store with "own key"), and make it the same key as the Google Play app signing key if the studio holds that key. Reasons: RuStore and Aptoide ask for it, Android developer verification registers each package and certificate pair, and fewer keys mean fewer registrations and fewer lost-key risks. Trade-off: with one key, a newer versionCode from any store can replace another store's build and switch its billing SDK; Android 14+ asks the user to approve updates from a store that is not the update owner. If overwrites are unacceptable for a store, give that store its own package name rather than its own key. Register every resulting certificate (including Amazon's) in developer verification.
2. 16 KB timeline: Unity staff quote Google's 2025-11-01 requirement for new apps and updates, while the current Android page says non-compliant updates are blocked from 2027-02-01. Treat 16 KB as required now because the game targets API 36.
3. Unity 2022.3 and 16 KB packaging: every 2022.3 patch bundles AGP 7.4.2, below Google's AGP 8.5.1 guidance; Unity says 2022.3.56f1+ supports 16 KB, but a user reports Play rejections with 2022.3.71f1 (https://discussions.unity.com/t/unity-2022-3-71f1-android-playstore-16-kb-page-size-not-working/1706445, third-party). Also 6000.0.38f1-44f1 bundle AGP 8.3.0, and Google notes that with AGP 8.3-8.5 bundletool does not zipalign APKs. Inference: prefer 6000.0.45f1+ and run the zipalign check on bundletool output for every build.
4. Yandex Mobile Ads Android SDK 8.6.0 requires AGP 8.7.0+, which no Unity 2022.3 patch bundles. Whether the Yandex Unity plugin builds with Unity 2022.3 was not verified.
5. Unity 2022.3 support: Unity's blog promises full support "until at least May 30, 2025" plus one year for Enterprise; the 2022.3 manual says two years for Personal/Pro and three for Enterprise/Industry. Unity staff list 2022.3.72f1 (2026-02-11) as "2022.3 xLTS"; a user comment says it is limited to Enterprise/Industry licenses. Without xLTS access a 2022.3 project cannot get UIScene support (needed when building with Xcode 27); use 6000.0.68f1+ or 6000.3.8f1+.
6. Xcode 26 and Unity: no official Unity statement names the minimum 2022.3 or 6000.0 patch for Xcode 26 builds. A user reported 2022.3.62f1 working with Xcode 26.4 (search result, not fetched). Unity 6000.7 docs state Xcode 26 or later is required.
7. iOS minimum: Apple requires iOS 13+ for uploads since 2026-09-09, but Apple's Xcode support table lists iOS 15-26 as the Xcode 26 deployment range for uploads. Verify in Xcode whether iOS 13 or 14 deployment targets still archive and upload; rule 91 recommends iOS 15.
8. Play size limits: the Play Console help page now lists 500 MB for the base module, while the Unity 6000.0 Player settings page still says Split Application Binary is required above 100 MB and older documentation cites 200 MB. The Play Console page was used.
9. Android developer verification and non-certified devices: verification applies to certified Android devices and is delivered through Google Play services. Inference, not confirmed: Huawei devices without GMS and Amazon Fire tablets are not checked. Developers in comprehensively sanctioned countries cannot complete verification and checks do not run on devices located there; whether this covers Russia is not stated by Google or RuStore.
10. Huawei AppGallery: official pages for target API, 64-bit and APK size limits could not be fetched. A 2023 third-party report says targetSdkVersion 30+ for new apps (enforced from 2023-10-31) and a Huawei notice (seen only in search results) says 32-bit-only packages are not accepted since 2022-09-01. Huawei IAP, HMS Unity plugin versions, Petal Ads regions and the official OAID guide were not verified.
11. Xiaomi GetApps: no official technical requirements found. The GetApps team post (third-party host) says each package and signing key pair must be registered for developer verification. A third-party integrator cites com.xiaomi.billingclient:billing 1.1.3 as the GetApps billing SDK (search result only).
12. Epic Games Store (Android): reports say mobile self-publishing opened in August 2026 through the Mobile Early Adopter program with 88/12 for Epic payments and 0% for third-party payments; Epic's mobile news page returned HTTP 403 and no developer technical requirements (format, signing, target API, billing SDK) were found.
13. RuStore Pay SDK and Unity: RuStore documentation (seen in search results; pages returned HTTP 429) says the SDK works correctly only with UnityPlayerActivity, not GameActivity, and needs Java 17 from Pay SDK 10.2.0 with Unity 2022.3.37f1+. Verify the Application Entry Point of the RuStore build.
14. Amazon Appstore: the Fire OS minimum target table has no effective dates for Fire OS 14 and 16; the Amazon Appstore SDK Unity plugin 3.0.2 is ARMv7 only while Amazon says some Fire devices no longer run 32-bit apps, so the Fire build needs either an ARMv7-only binary or the 3.0.8 SDK with a custom bridge.
15. Samsung: the target API >= 33 rule comes from an undated FAQ; a newer floor may exist. Samsung IAP minSdk was not verified.
16. APK signature schemes v3 and v4: no store page stating acceptance or rejection was found.
17. Consent: AdMob's CMP page does not name a TCF version; TCF v2.3 comes from IAB Europe. GPP is optional for AdMob (RDP is the alternative). OAID handling for Huawei and Xiaomi devices was not verified on an official page.
18. ATT: whether calling the ATT request without NSUserTrackingUsageDescription crashes the app was not verified on Apple's page; AdAttributionKit is available from iOS 17.4 (https://developer.apple.com/documentation/adattributionkit) and shares ad network IDs with SKAdNetwork (https://developer.apple.com/documentation/adattributionkit/adattributionkit-skadnetwork-interoperability).
19. Unity predictive back: the first 2022.3 and 6000.0 patches containing the Predictive Back Gesture Support setting were not found; Android 16 behavior must be tested on a device for each Unity version in use.
